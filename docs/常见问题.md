# 常见问题

---

## 概念

**Q：线路、档案、内核，这三个词是什么关系？**

- **线路** = 一个订阅（或一个本地代理端口），配一对本地端口，背后是一个内核进程。
- **档案** = 「某个程序 × 某条线路」。档案是你要点的那东西，线路是它在用谁。
- **内核** = 真正干活的进程（sing-box / xray），按需起，没人用就退。

点「启动」的时候：查档案绑了哪条线路 → 那条线路的内核没起就先起它 → 带着代理参数把程序拉起来。

**Q：图标右下角的小圆标是什么？**

线路短码。`D` 是直连（不绑线路），其余是线路 id 的前三个字母。同一软件建了多个档案时，靠它区分。

**Q：为什么菜单里说「全部停止」而不是「全部关闭」？**

「停止」指停止这些软件对应的内核和进程。软件本身你想开就开，关了程序内核会自己退。

## 使用

**Q：点了启动，软件开了但好像没走代理？**

按顺序查三件事：

1. **这个程序认不认代理参数**。Chrome / Edge 认 `--proxy-server`；很多 Electron 客户端、游戏、后台更新器**不认**。不认的只能开 TUN（设置 → TUN）。
2. **主界面详情里的「代理链路」是不是绿的**。内核没起来时，程序会带着一个连不上的代理地址被拉起（表现就是打不开网页）。
3. **程序自己有没有内置代理设置覆盖了环境变量**。有些客户端有「使用系统代理 / 直连」的选项，会无视我们给的环境变量。

**Q：需要管理员权限吗？**

- 主用法（塞代理参数、系统代理、开机自启）**完全不需要**。
- 只有 TUN 需要，而且只在第一次开启时弹一次 UAC（装一个最高权限的计划任务），之后不再弹。

**Q：会不会和我现在用的 v2rayN / Clash 打架？**

不会，只要你别同时让两边都接管系统代理。本软件接管系统代理前会**备份原值**，关闭时原样写回；如果检测到你原来已经指着别的端口，还原时会还回去。

**Q：我不想动系统代理，只想让某个软件走代理。**

那就别开系统代理。这正是本软件的主要用法 —— 每个软件带着自己的代理参数启动，系统层面什么都不改。

**Q：关掉主界面窗口，正在用的软件会断吗？**

不会。关窗口只停本地 HTTP 服务，内核和已经开着的软件照常。内核该不该退，由「还有没有程序在用」决定。

**Q：程序关了，内核为什么不立刻退？**

有 60 秒宽限期 —— 防止你「关掉又马上重开」时反复起停内核。实际回收检查每 5 秒跑一次。

**Q：同一个 Chrome 能同时开三个窗口走三条不同线路吗？**

可以。每个档案有自己的 `--user-data-dir`（独立配置目录）和自己的本地端口，三个窗口互不共享 cookie，也互不影响线路。

**Q：为什么列表里显示「未运行」，但我明明开着这个程序？**

浏览器是按 `--user-data-dir` 精确匹配的 —— 你自己双击开的 Chrome 用的是默认配置目录，不是本软件建的档案目录，所以算「另一个 Chrome」。用档案的图标启动才会被认成同一个。

## 数据与隐私

**Q：我的订阅地址会被上传吗？**

不会。所有数据都在 `D:\AppProxy\` 本地目录里，软件没有云端账号、没有遥测、不向外发任何请求（除了你自己的订阅地址和测速目标）。

**Q：订阅地址存在哪？**

`D:\AppProxy\data\lines.json`，明文。里面有 token（访问令牌），**不要把这个目录发给别人**。

**Q：想换台电脑，怎么搬？**

整个 `D:\AppProxy\` 目录拷过去就行（含线路、档案、图标、快捷方式母版）。到新机器上重跑一次 `scripts\setup.bat` 和 `scripts\fetch_engine.py`，再让软件重建桌面快捷方式（主界面详情里的「重做图标与快捷方式」）。

**Q：怎么彻底卸载？**

1. 托盘 → 退出；
2. 设置 → 关掉开机自启、关闭系统代理（会还原原值）；
3. 设置 → TUN → 如果开过，先「关闭 TUN」再 `python -m appproxy.cli tun remove`（删计划任务）；
4. 删掉项目目录和 `D:\AppProxy\`；
5. 桌面上的 `.lnk` 自己删。

没有服务、没有驱动残留（TUN 的虚拟网卡随内核进程退出而释放）。

## 排错

**Q：主界面一片空白 / 打不开。**

先确认端口没被占：`netstat -ano | findstr 1443`。界面会把实际端口写进 `D:\AppProxy\gui.port`。

如果界面能打开但内容空白，几乎都是**系统代理把 `127.0.0.1` 也送进代理**导致 —— 本软件已经把 `ProxyOverride` 写好、窗口也带 `--no-proxy-server`；如果你自己另装了别的代理软件并接管了系统代理，把它关掉再试。

**Q：内核起不来。**

看 `D:\AppProxy\logs\` 下的日志（文件名是 `<内核名>-<线路id>.log`）。最常见两个原因：

- 找不到 `sing-box.exe`：没跑 `scripts\fetch_engine.py`；
- 端口被占：线路的本地端口（10801 起）撞了别的程序。

**Q：订阅更新后节点全没了。**

先看「更新订阅」的返回信息。如果订阅地址需要特定 UA（很多机场对 UA 有要求），或者返回的是 HTML 而不是节点列表，会明确报「没解析出节点」。

**Q：TUN 开了之后游戏卡 / 反作弊报错。**

TUN 是整机流量接管，个别反作弊会把它当成 VPN 拦截。这类游戏建议关掉 TUN，用普通模式（或者干脆不用代理玩）。这也是 TUN 默认关的原因。

**Q：TUN 开启失败，提示要管理员权限。**

点「开启 TUN」时会**自己弹**「用户账户控制」，点「是」即可。如果你在弹窗前就点了取消，或者系统策略禁止提权，界面会明确说明。

自检工具：`python tools\verify_tun.py`（会逐步打印、最后弹窗给结论，报告在 `D:\AppProxy\logs\tun-verify.txt`）。

## 开发

**Q：为什么内核不在仓库里？**

`sing-box.exe` 有 79 兆字节，超过 GitHub 建议的单文件体积，clone 会很慢。跑一次 `python scripts\fetch_engine.py` 即可。

**Q：为什么不直接改 sing-box 源码？**

两个原因：一是 GPL 传染 —— 把 GPL 代码合并进本项目，整个项目都得按 GPL 发布；二是没必要 ——「分应用」这件事用 `process_name` 路由规则 + 独立端口就够了。现在的方式是独立 exe、独立进程调用、不改源码。

**Q：想加一个「明显需要代理」的软件。**

编辑 `appproxy/data/apps_need_proxy.json`（或 `D:\AppProxy\data\apps_need_proxy.json`，后者优先级更高、整份覆盖）。只按进程名匹配，写 `chrome.exe` 这种，不要写路径。
